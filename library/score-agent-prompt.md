请把用户上传的简谱转换成“口风琴模拟”可以导入的 JSON。先完整读取项目里的 `library/import-example.json`，严格沿用其中的字段结构，不要自行设计格式。

外层固定为：

```json
{
  "app": "口风琴模拟",
  "version": 1,
  "exportedAt": "ISO时间",
  "library": [ { "id", "title", "source", "createdAt", "events": [ ... ] } ]
}
```

每个事件必须包含：

- `t`：按键开始时间，单位秒
- `d`：按键持续时间，单位秒
- `key`：`z` / `x` / `c` / `v` / `b` / `n` / `m`（小写，对应简谱 1～7）。高音 1 用 `,`，不要再标 right
- `note`：简谱数字字符串（`"1"`～`"7"`）
- `mouse`：高低音控制

高低音规则：

- 无圆点：中音，`mouse: []`
- 数字上方圆点：高音，`mouse: ["right"]`
- 数字下方圆点：低音，`mouse: ["left"]`
- 半音：`mouse: ["middle"]`
- 八度优先于半音：同时要升降八度又要半音时，保八度、丢半音
- 不支持和弦：谱里和弦只取第一个音

工作要求：

1. 先逐行人工核对谱图，列出每行的数字、八度和分句，不得只依赖 OCR。
2. 谱图里的竖线、明显空格或左右分栏都代表分隔。分隔处必须留停顿，不能把前后音直接连起来。停顿只加大后一个音的 `t`，不要把前一个音的 `d` 拉到和下一个重叠。
3. 音符顺序必须严格照谱图，不得根据歌曲印象补音、删音或换音。
4. 如果同时提供了录屏视频：
   - 先确认视频中真正开始演奏简谱的时间。
   - 只检测整体 BPM、拍点、分句入口和休止。
   - 音符吸附到拍点、半拍或四分之一拍。
   - 不要把每个音强行吸附到人声字头。
   - 不得为了匹配频谱把多个音挤进 0.05～0.15 秒。
   - 除非谱面明确表示快速装饰音，相邻起音应保持合理间隔。
5. 如果没有演奏音频，不要声称已经与原曲同步。采用合理的稳定 BPM，并在 `source` 里明确标注这是估算节奏。
6. 音符发声长度通常占相邻起音间隔的 80%～92%；分句处应提前松键，留下真实静音。
7. 一字多音只能依据谱面数字数量处理，不能依据歌词字数擅自增删音符。
8. 如果收到两张同一歌词但数字不同的谱，它们可能是不同编配，必须分别处理，绝对不能拼在一起。

生成后必须检查：

- JSON 可以正常解析
- 没有事件重叠（`t + d` 不超过后一个音的 `t`）
- `d > 0`
- 所有 `key` 均在 `z x c v b n m ,` 中
- 相邻音没有异常连发
- 分句处确实存在停顿

最终只输出可复制导入的单曲 JSON（上面的 `app/library` 结构）。用户把它贴进软件「导入 JSON」即可，不用重启。另附简短报告：音符总数、BPM、总时长、最短起音间隔、分句数量以及无法确定的位置。无音频时不要声称已与原曲同步。
